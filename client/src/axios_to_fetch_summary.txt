OVERVIEW
--------
Removed axios entirely and replaced with native fetch. No component logic
changed. The apiFetch helper preserves the exact response/error shape that
components already depend on.

--------------------------------------------------------------------------------
FILES CREATED
--------------------------------------------------------------------------------

client/src/services/apiFetch.js
  Shared fetch wrapper used by both service files.

  Success path:
    - Calls fetch with Content-Type: application/json header
    - Parses response.json()
    - Returns { data: <parsed JSON> }
      → matches axios's res.data shape
      → GeneratorPage reads res.data?.data?.destinations — unchanged

  Error path:
    - On !response.ok, throws an Error with:
        err.message  = data.message or fallback string
        err.response = { status: response.status, data: <parsed JSON> }
      → matches axios's err.response shape
      → GeneratorPage reads err?.response?.data?.message — unchanged
      → DestinationCard reads err?.response?.status and err?.response?.data?.code — unchanged

  BASE_URL:
    - Still reads import.meta.env.VITE_API_BASE_URL || ''
    - Vite proxy and production env var behaviour identical to before
