OVERVIEW
--------
Click limits are now enforced in the database. The service counts real DB rows,
enforces a hard limit of 5 clicks/month, persists accepted clicks, and returns
remaining_clicks. The controller response shape is unchanged (data now just
includes the new field). The error handler now forwards err.code so the frontend
LIMIT_REACHED detection works via both HTTP status and response body.

server/migrations/001_create_clicks_table.sql
  - Creates flight.clicks table:
      id             SERIAL PRIMARY KEY
      user_id        INTEGER NULL          (NULL until auth)
      destination_id INTEGER NOT NULL
      click_type     VARCHAR(10) NOT NULL  CHECK ('flight' | 'hotel')
      created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
  - Creates index on (user_id, created_at) for fast monthly count queries

  TO RUN:

server/src/services/clicks.service.js  [REWRITTEN]

  MONTHLY_CLICK_LIMIT = 5  (const at top — easy to change)

  trackClick({ destination_id, click_type }):
    1. userId = null (no auth yet)
    2. COUNT clicks this calendar month WHERE user_id IS NOT DISTINCT FROM $1
       - IS NOT DISTINCT FROM is used instead of = because NULL = NULL is false
         in SQL — this operator correctly matches NULL to NULL
    3. If usedThisMonth >= 5:
         throw { message, status: 429, code: "LIMIT_REACHED" }
    4. INSERT INTO flight.clicks (user_id, destination_id, click_type)
    5. Return { destination_id, click_type, remaining_clicks }
       remaining_clicks = MONTHLY_CLICK_LIMIT - (usedThisMonth + 1)

  Anonymous quota note:
    With user_id = NULL, all anonymous browser sessions share one global counter.
    This means the limit of 5 applies across ALL users until auth is added.
    This is expected — the note is in the service code. Scope to real user IDs
    by replacing `null` with the authenticated user's ID when auth is ready.

server/src/middleware/errorHandler.js  [MODIFIED]
  - Added: if (err.code) body.code = err.code
  - The error response now includes code: "LIMIT_REACHED" when thrown by the service
  - Frontend resolveCtaError() checks both status === 429 AND code === "LIMIT_REACHED"
    — both now work correctly

server/src/controllers/clicks.controller.js  [NO CHANGE NEEDED]
  - Already returns `data` from trackClick — remaining_clicks flows through automatically
  - Response shape is now: { ok, message, data: { destination_id, click_type, remaining_clicks } }
