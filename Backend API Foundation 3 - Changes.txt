server/src/repositories/destinations.repository.js
  All parameterized SQL queries. Five functions:

  getTripTypeBySlug(slug)
    SELECT id, slug, label FROM flight.trip_types
    WHERE slug = $1 AND is_active = true

  getSimilarTripTypeIds(tripTypeId, minScore)
    SELECT similar_to_id FROM flight.trip_type_similarity
    WHERE trip_type_id = $1 AND similarity_score >= $2

  getCandidateDestinations(tripTypeIds, departureAirportId, excludeIds)
    SELECT DISTINCT d.* FROM flight.destinations d
    JOIN flight.destination_trip_types dtt ON dtt.destination_id = d.id
    WHERE d.departure_airport_id = $1
      AND dtt.trip_type_id = ANY($2::int[])
      AND d.is_active = true
      AND d.id != ALL($3::int[])    <- safe with empty array

  getTripTypesForDestinationIds(destinationIds)
    SELECT dtt.destination_id, tt.id, tt.slug, tt.label, dtt.is_primary
    FROM flight.destination_trip_types dtt
    JOIN flight.trip_types tt ON tt.id = dtt.trip_type_id
    WHERE dtt.destination_id = ANY($1::int[])

  getRecommendedPlacesForDestinationIds(destinationIds)
    SELECT destination_id, name, description
    FROM flight.recommended_places
    WHERE destination_id = ANY($1::int[])
    ORDER BY destination_id, sort_order

server/src/services/destinations.service.js
  Full 4-tier fallback orchestration:

  Affordability formula:
    estimated_total_cost =
      (flight_cost_per_person_gbp * travellers)
      + (ceil(travellers / 2) * hotel_cost_per_night_gbp * default_duration_nights)

  Tiers (in order):
    tier1_exact        exact trip type,    budget <= budget
    tier2_exact_flex   exact trip type,    budget <= budget * 1.10
    tier3_similar      similar types,      budget <= budget
    tier4_similar_flex similar types,      budget <= budget * 1.10

  - similar types: similarity_score >= 6 only
  - deduplication: excludeIds passed to repo on each tier
  - randomization: shuffle() applied after budget filter
  - max 3 results total across all tiers
  - after selection: fetches trip_types + recommended_places in 2 parallel queries
  - assembles final nested response

HOW THE FALLBACK FLOW WORKS
---------------------------------------------------

1. Resolve the requested trip_type_slug to a trip_type row.
   If slug is unknown, return 0 results immediately.

2. Look up similar trip type ids from trip_type_similarity
   where similarity_score >= 6.

3. Run up to 4 tiers in order, stopping when 3 destinations
   are collected:

   Tier 1 — exact trip type ids, strict budget
   Tier 2 — exact trip type ids, budget + 10%
   Tier 3 — similar trip type ids, strict budget
   Tier 4 — similar trip type ids, budget + 10%

   Each tier:
   - Queries candidates excluding already-selected ids
   - Computes estimated_total_cost per destination in JS
   - Filters out unaffordable results
   - Shuffles remaining candidates (randomization)
   - Takes only as many as still needed to reach 3

4. After final set is selected:
   - Fetch trip_types for all destination ids (1 query)
   - Fetch recommended_places for all destination ids (1 query)
   - Assemble nested response

5. meta.fallback_used = true if tier1_exact was not hit.
   meta.tiers_hit lists every tier that contributed results.
