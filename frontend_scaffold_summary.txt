BACKEND RESPONSE SHAPE CONSUMED
--------------------------------------------------------------------------------

POST /api/destinations/generate
Response: { ok, message, data: { destinations[], meta, request } }

Each destination:
  destination_id, city, country, hook, fun_fact, weather_summary,
  flight_cost_per_person_gbp, hotel_cost_per_night_gbp, default_duration_nights,
  estimated_total_cost, trip_types[], recommended_places[],
  skyscanner_url, booking_com_url

A few things to note:

Mood slugs — I used beach, city-break, adventure, cultural, skiing, relaxation as guesses. Update moodOptions.js to match the actual slug values in your flight.trip_types table.

Vite proxy — The dev server now forwards /api/* to http://localhost:5000, so no CORS issues in dev. For production, set VITE_API_BASE_URL in a .env file.

Departure airport — DEPARTURE_AIRPORT_ID = 1 is in GeneratorPage.jsx:7. When you add a selector later, just promote it to form state and remove the constant.

Card links — skyscanner_url and booking_com_url are rendered as anchor tags only when present in the backend response — no broken links if the DB rows don't have them yet.
