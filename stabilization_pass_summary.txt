PART 5 — MOOD SLUG SAFETY
--------------------------------------------------------------------------------

client/src/constants/moodOptions.js  [MODIFIED — comment only]
  - Added prominent warning that slugs are unverified against the DB
  - Added the exact SQL query to run for verification:
      SELECT slug, label FROM flight.trip_types WHERE is_active = true ORDER BY slug;
  - Added recommendation for a future GET /api/trip-types endpoint as the
    long-term fix for frontend/backend slug drift

IMPORTANT — THE SLUGS CANNOT BE VERIFIED FROM THIS REPO:
  There are no SQL migration or seed files committed. The slug values
  (beach, city-break, adventure, cultural, skiing, relaxation) are guesses
  based on common travel categories. You MUST run the query above against
  your database and update moodOptions.js before launch.

  If a slug doesn't match a DB row, the mood option will silently return
  zero destinations — no error, no warning.
